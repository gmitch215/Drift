# Answer key, scenario 5 (never shown to readers)

Cause: `there` starts the container with `--ulimit nofile=64:64`, so the process may hold 64 open files. The check opens 300.
Attribute: `limits.nofile` (here the default, there 64).
Fix: raise the open-file limit (`ulimit -n 1024` or the runner's setting), or close files in the check.
