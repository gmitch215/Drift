Classification

unclassified, basis verified; causes: platform-defined, Kotlin issue, JDK version.

No explanation was found in the sources searched.

One example is Double.toString(2e23), which now returns "2.0E23", whereas in earlier releases it returns "1.9999999999999998E23"

https://www.oracle.com/java/technologies/javase/19-relnote-issues.html

as many, but only as many, more digits as are needed to uniquely distinguish the argument value from adjacent values of type double

https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/Double.html

This decimal is (almost always) the shortest one that rounds to m according to the round to nearest rounding policy

https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Double.html

Notes

Three groups differ from the majority. jvm-17 and android print the pre-JDK-19 digits (1.9999999999999998E23 for 2e23): the JDK 19 release note JDK-4511638 explains jvm-17 (verified), and Android matching the old algorithm is observed, the Android Double page read carries the old spec text. The wasm family prints 1.9999999999999998e+23 and plain forms (KT-88414 Fixed, equal on 2.5.0-Beta1). js-ir prints the ECMAScript shortest digits (2e+23, 1e+23) and 0.1f as 0.1 because a Float is a double there; its lines are unchanged on 2.5.0-Beta1 (measured with the standalone compiler). Android is still the odd column on 2.5.0-Beta1. cloudflare-wasm prints what wasm prints; cloudflare-jvm prints what ios, jvm, jvm-21, jvm-25 and 3 more print.

What is known: Three groups differ from the majority. jvm-17 and android print the pre-JDK-19 digits (1.9999999999999998E23 for 2e23): the JDK 19 release note JDK-4511638 explains jvm-17 (verified), and Android matching the old algorithm is observed, the Android Double page read carries the old spec text. Android is still the odd column on 2.5.0-Beta1. cloudflare-wasm prints what wasm prints; cloudflare-jvm prints what ios, jvm, jvm-21, jvm-25 and 3 more print.

What is NOT known: whether the divergent column is a defect or by design where no page read states the intended behavior; whether a newer compiler or stdlib than 2.5.0-Beta1 changes the result; whether a different device, runtime or workerd release of the same target differs (one run per cell); whether a TeaVM or bytebox release other than 0.15.0 and 1.0.3 changes the cloudflare-jvm column; whether the displayed snippet and the executed probe body are identical (they are two hand-written copies).
