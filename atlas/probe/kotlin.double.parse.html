No explanation was found in the sources searched.

This decimal is (almost always) the shortest one that rounds to m according to the round to nearest rounding policy

https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Double.html

Notes

Wasm family and js-ir both return null for 0x1p3, 1d and 1f, for different reasons. Wasm: KT-88414 Fixed (Kotlin/Wasm used its own parser); equal on 2.5.0-Beta1. js-ir: the parser is ECMAScript StringToNumber behind a NaN guard, which has no hex float and no d or f suffix; the same route accepts 0x10 (KT-72509 Open) and the guard keeps the string nan (no tracker item). js-ir also prints Float values outside the single precision range (float-above-max, float-1e39) and 1e-400 as 0. js-ir lines are unchanged on 2.5.0-Beta1 (measured with the standalone compiler). KT-72508 (Open) says the toDouble pages give no accepted formats, so no line is documented. cloudflare-wasm prints what wasm prints; cloudflare-jvm prints what android, ios, jvm, jvm-17 and 5 more print.
