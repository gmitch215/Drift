Classification

platform-defined, basis verified; causes: platform-defined, build tool.

Note that the pattern syntax and the option set has differences on each platform.

https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.text/-regex/

but also matches just before the last line terminator if this is not followed by any other input character

https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/regex/Pattern.html

Notes

js-ir differs from every other column on seven lines: the four dollar-before lines, dollar-count-plain, caret-count-multiline and nel-multiline. Java Pattern and ECMAScript define $, ^ and the line terminator set differently (Java: $ also matches before a final line terminator, U+0085 is a terminator; ECMAScript: $ matches at the end of input only without m, ^ with m matches after a final terminator, no U+0085), and the Kotlin Regex page says the syntax differs on each platform. KT-82450 (Submitted) reports the same class of difference on JS. cloudflare-jvm records the probe as unavailable: the build replaces the matchAt lines with a thrown UnsupportedOperationException because Matcher.useAnchoringBounds is reported missing from the class library, yet TeaVM 0.15.0 (the version bytebox 1.0.3 pins) TMatcher declares it, so the cause of the refusal is not confirmed. The probe is unchanged on js-ir at 2.5.0-Beta1. cloudflare-wasm prints what wasm prints.
